The problem

Agents read untrusted text. And they act on it.

AI agents now hold API keys, tools and customer data. Controls live inside each app or each model vendor, so a bank cannot define them once, enforce them everywhere and prove what happened.

What Tollgate is

One gateway. One policy file.

  • An OpenAI-compatible proxy. Change two settings, base URL and API key; works with the official OpenAI SDK.
  • Every request and response passes through it, including tool definitions and tool calls.
  • policy.yaml is the control catalog: controls, actions, thresholds, models, budgets, feed.
  • Runs locally: Ollama models, SQLite, hash-chained audit log, Next.js dashboard. No cloud APIs.

How it decides

Rules first. Models only when unsure.

Deterministic checks decide most requests in about half a millisecond. A local model looks only at what the rules cannot decide, and a judge only when that model is unsure. Responses are scanned too.

Policy engine

Edit the file. The next request obeys it.

  • Strict schema: a misspelt key or wrong value is rejected with the exact path; the last good policy stays active.
  • Every decision records the policy hash it was made under.
  • monitor mode records "would block" and lets traffic pass; enforce acts.
  • Presets: standard, strict (fail-closed), monitor.

Budgets

Budgets per agent, checked before spending.

  • Tokens per hour, USD per day (priced per model, local models at $0), compute seconds, requests per minute, tool depth.
  • Estimated before the call, reconciled after. Over budget: 429 with the rule id.
  • Loop breaker: the same request 5 times in 30 s is blocked. Circuit breaker for a failing upstream.

Reporting and audit

For managers and for the security team.

  • Overview: posture score, blocks over time, spend per agent, latency per stage.
  • Security: every decision with rule, tier, OWASP id and redacted excerpt; filters; JSONL and CSV export.
  • Audit log: each line holds the hash of the previous one; audit:verify finds the first tampered line.

Limits and next steps

What it does not do yet.

  • Semantic checks are bounded by small local models; bypass rates are published.
  • Streaming is buffered: the full answer is scanned before it is sent.
  • Single node with SQLite; the audit chain is tamper-evident, not tamper-proof.
  • Not covered: OWASP LLM08, LLM09, ASI09.

Next

  • MCP transport proxy with tool-manifest pinning.
  • Model-file scanning.
  • Shared budget counters for many instances.
